Local-first Architecture

核心猎头数据默认留本地

本地数据库 + 本地文件 + AI Gateway。需要更强模型时，再按企业政策脱敏调用云端模型。

TalentOS UI

React / Next.js + Tauri 或 localhost Web。Search Project 是核心 Workspace。

→

AI / Workflow Layer

Job Agent · Talent Agent · Report Agent · Orchestrator。规则和Human Gate共同控制。

→

Local Data Layer

SQLite + Local Files + Search/Embeddings。后续多人版再升级PostgreSQL / 内网Server。

AI 负责

Research、JD解析、Success Profile初稿、Search Strategy、CV解析、证据匹配、访谈总结、Assessment初稿、Shortlist报告、异常监控。

顾问负责

理解客户、校准真实需求、判断候选人、建立关系、处理例外、最终推荐、商务谈判与成交。

Core Objects Client └── Search ├── SuccessProfile ├── TargetCompany └── Candidate ├── Interaction ├── Assessment ├── Interview └── Offer 原则：AI 输出 ≠ 事实。所有关键判断保留 source / evidence / human confirmation。
Validation

Sprint 1 成功，不看功能数量

只看真实职位是否跑通，以及顾问是否愿意把第二个职位继续放进 TalentOS。

Job Intake Time ↓需求整理是否提速
Market Mapping Time ↓Research是否提速
CV Review Time ↓筛选是否提速
Modification Rate ↓AI初稿需要改多少
Shortlist Time ↓整体Search是否更快

Golden Case 验收

1个真实JD → 1个Success Profile → 10+ Candidate → 5个AI Match → 3个Interview Notes → 3个Assessment → 2–3人Shortlist → 1份客户报告。

GO：顾问愿意把第二个真实职位继续放进系统。 ITERATE：有价值但修改量太高。 STOP：顾问依旧明显更愿意使用微信 + Excel + Word。
